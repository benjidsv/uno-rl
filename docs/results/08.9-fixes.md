# Step 8.9: fixes before AIVAT (2026-09-15)

> On top of commit `8bb6009`. Rerun: `uv run pytest` (102 tests, 3 min 48 s), then every experiment with `caffeinate -is bash scripts/rerun_all.sh` (one log per step in `logs/`).

Three fixes from the review before step 9, and what was checked for AIVAT. No
number of a named toy changes.

## 1. Deal probabilities with duplicate cards

`uno.game.chance._multisets` gives the probability of each hand multiset; it
feeds `initial_deals`, hence the census, the sizing DP, the compiled trees and
the reference solvers. It multiplied by the number of orderings of a multiset
at every level of its recursion instead of once. From 3 cards on, with
duplicate cards in the deck, the probabilities were wrong: 3 cards from
{a, a, b, c, c} got masses summing to 1.7, with wrong ratios ((a, b, c) 0.8
against 0.4, (a, c, c) 0.2 against 0.2). After `initial_deals` normalised them,
deal probabilities on a 7-card deck with duplicates were off by up to 0.8
points. It is now the multivariate hypergeometric `prod_t C(c_t, m_t) / C(N, n)`,
with the multisets in the same order as before.

Not affected: every named ruleset. They have one copy per card, so the error
was the same factor on every hand and the normalisation removed it: every exact
solve, CFR result and ladder number stands. Hands of 1-2 cards were always
right, and the solver tests only generate those, which is why no test caught it.

Affected: the two step 8.7 sizing rows with duplicates and a hand of 3. Their
sizes are unchanged; their random-vs-random seat-0 score moves (exhaustion, tie
and length columns unchanged at the table's precision):

| candidate | as reported in 8.7 | fixed |
|-----------|--------------------|-------|
| 3c(2,1)+W forced | 0.6602 | 0.6615 |
| 3c(2,2)+W forced | 0.6667 | 0.6638 |

"Duplicates and short piles go the wrong way" stands; [step 8.7](08.7-toy2.md)
is corrected.

Tests, each of which fails when the old `_multisets` is patched back in:
`test_multisets_are_hypergeometric` (every n-subset of random small decks),
`test_initial_deals_with_duplicates_hand_3` (two 7-card decks with duplicates
against every permutation), `test_initial_deals_match_permutations` (random
rulesets up to 7 cards, any hand size) in `tests/reference/test_census.py`, and
the regression pin `test_duplicates_pinned` in `tests/reference/test_sizing.py`
(3c(2,1)+W: 736 orbits, 282,509 histories, random vs random 0.66153, uniform
legal 0.65331).

## 2. Agent names key the action rng

The action rng of `uno.eval.play` is seeded from (seed, agent name, information
state). Two different agents with the same name would draw the same numbers at
the same seat of the two games of a mirrored pair, coupling them beyond the
deal, silently, and breaking the independence `exact_mirrored` assumes.
`play_pairs` now raises in that case; self-play passes the same object twice
(the one test that built two `PlayFirstRandom` objects was changed).

Why the name and not the object (`id`): an `id` changes every run, so no sampled
number would reproduce, and two objects of the same policy (built by two
experiments, or a checkpoint loaded twice) would lose common random numbers,
which `compare` relies on. The rule is that a name identifies a policy. Watch
the defaults `CompiledAgent(name="compiled")` and `CFRResult.agent(name="nash_l1")`:
give checkpoints and Nash variants their own names.

## 3. Cache version

`uno.store.CACHE_VERSION` (1) is written into every tree and CFR file. A file
with another version, or with none (everything written before this step), is
stale: `compile_tree(cache=...)` recompiles and overwrites it, and `load_nash`
ignores it, so the CFR runs again. Bump it whenever the engine, the chance
model, the keys, the symmetry or the tree layout change what a compile
produces. Tests: `test_stale_cache_is_recompiled` (`tests/game/test_symmetry.py`)
and the stamp check in the CFR save round trip.

## 4. Checked for step 9, nothing to change

- **A real state can be looked up in the tree.** On the full `TOY` tree the L2
  keying has exactly one node per set (876,848 decision nodes, 876,848 L2 sets):
  the L2 key of a played state is its node. So V(state) is the node value under
  the profile being evaluated, and the expectations AIVAT subtracts are arc
  values (decisions: `sum_a pi(a) av[a]`; draws: the draw arc's value over its
  chance edges).
- **On the quotient,** up to 6 nodes share a canonical L2 set (4,139 of 18,620
  sets); under Heuristic vs Random their values agree to 1.1e-16, as they must
  for a symmetric profile. An arc there has to be found through its set-action
  (the real action mapped by the canonicalising element), because a quotient
  node's `arc_action` is written in that node's own labels. The full `TOY` tree
  (`tree_TOY_L1L2_full.npz`) avoids the question for a first implementation.
- **The traces are enough:** every `Step` holds the acting player's
  probabilities, so corrections at chance, the evaluated agent and the opponent
  are all available.
- **The M1 on-seeds check does not apply to AIVAT.** AIVAT removes the deal and
  pile luck that the on-seeds value keeps, so over a seed range it estimates the
  global exact value; check it against that, with its own sampled variance.

Left from the review: the module docstring of `uno/game/symmetry.py` still says
canonicalising an observation is enough to symmetrise an agent (corrected in the
spec in step 8.8), and `uno.game.chance` has no chance model for a reshuffle,
which AIVAT on `FULL_UNO` will need.
